HR on WhatsApp: the bot answers, the team takes over.

An HR support bot integrated with Meta's official WhatsApp API. Employees resolve time clock, payroll and benefits questions on their own with step-by-step tutorials; when they need a person, they pick a topic and join a queue that HR follows in a dashboard similar to WhatsApp Web.

00 · The challenge

The same questions, every day, over WhatsApp.

How do I clock in? Where do I see my timesheet? How do I send a medical certificate? Where is my income statement? Many of the questions that reach HR have a known answer that lives in a time clock app (Multi / My Ahgora) or in the Meu RH portal. Others need someone to look at the case.

The bot handles the step-by-step questions and hands HR, already organized, whatever needs a person.

SELF-SERVICE

Menus and tutorials

Time clock, payroll and benefits in numbered menus, with step-by-step instructions and a short video for each task.

QUEUE

Human support

The employee gives their name, picks a topic and joins an ordered queue; HR gets an email for every new request.

DASHBOARD

Support in the browser

HR sees the queue, takes over the conversation, replies with text or an attachment, closes and blocks, all from the same official number.

01 · Principles

The bot leads, but never runs over the person.

Four rules show up throughout the code, from the webhook to the dashboard:

01

When HR takes over, the bot goes quiet

In the manual state the webhook only logs the message and does not reply. Sending any message from the dashboard takes the conversation out of the queue and puts it in that state.

02

No conversation gets stuck

An invalid answer brings the menu back; 3 minutes of inactivity end the automated session; anyone in the queue can go back to the menu at any time.

03

The dashboard survives a restart

Messages, contacts, topics and blocks are stored in MongoDB. When the server starts, the history is reloaded and each conversation's status is inferred from its messages.

04

Respect Meta's limits

Sends are queued per recipient, with a minimum interval and a retry, and the dashboard shows a fixed notice: messages outside the 24-hour window may be charged.

02 · Conversation flow

From “hi” to a tutorial or the queue, in a few taps.

Every new conversation starts with a greeting and a request for the full name (at least two words with letters). Anyone who has already given their name goes straight to the menu. From there, each numeric answer leads to a tutorial, a submenu or the human queue.

03 · States and rules

One state machine per WhatsApp number.

Each conversation keeps track of where the employee is. There are 14 states, from idle to ended, and every incoming message is interpreted in light of the current state: the same “1” means Time clock in the main menu and “Clock in” in the submenu.

Bot in charge

await_user_name, await_main_choice, await_ponto_choice, await_folha_choice, await_back_menu.

Path to the queue

await_holerite_text, await_holerite_image, await_holerite_forward, await_human_topic, handover, await_handover_choice.

With HR or closed

manual (the bot does not reply), ended and idle (the next message starts over with the greeting).

The payslip question

It is the only path that collects material before reaching HR. The conversation is tagged Payslip right away and only moves on once it has both pieces:

Rules that prevent dead ends

Context recovery

If the state gets out of sync but the last menu sent (less than 5 minutes ago) was Time clock or Payroll, a valid number is redirected to the right submenu.

Writing while in the queue

The person chooses between returning to the main menu (and leaving the queue) or continuing to wait, without taking two spots in the queue.

Inactivity

Three minutes without a reply end the automated session with a thank-you message. The timer does not run for anyone in the queue or with HR.

Blocked contact

Messages from blocked numbers are ignored as soon as they hit the webhook, before any reply.

04 · WhatsApp Cloud API

A webhook to listen, the Graph API to reply.

The server talks to Meta through the WhatsApp Cloud API (Graph API v22.0). Meta delivers each employee message to the webhook; the server replies, logs it and notifies the dashboard in real time.

Send rate limit

ProblemSeveral messages in a row to the same number hit Meta's limit (error #131056, pair rate limit).
→
SolutionA promise queue per recipient, with a minimum interval of 900 ms (configurable) and one retry before logging the error.
05 · HR dashboard

A WhatsApp Web built for the HR queue.

The dashboard is a page served by the server itself at /admin, in plain HTML, CSS and JavaScript. The sidebar list is split into four tabs, with counters, search, and status and topic tags on each conversation.

In queue

People who asked for support, with their position (#1, #2…) and topic.

In progress

Conversations with HR and conversations where the bot is still active.

Closed

Sessions ended by HR, by the employee or due to inactivity.

Contacts

Editable display name and phone number; the real WaId does not change.

Dashboard actionWhat it does
Take overRemoves from the queue, stops the inactivity timer and sends “Atendimento Humano iniciado, nome. Pode me explicar sua dúvida?” (Human support started, name. Can you tell me your question?)
ReplyText or attachment (image, video, audio or document); the first reply already takes over the conversation
CloseSends the closing message; the employee's next message restarts the flow
StartSends a template to open the conversation outside the 24-hour window, with a notice about possible charges
Block / unblockCloses the conversation and makes the bot ignore the number

To stay live, the dashboard combines Server-Sent Events (with a heartbeat every 25 seconds to get through proxies) and polling every 5 seconds. A “fingerprint” of the list and the open conversation avoids redrawing the screen when nothing has changed, which used to make images flicker.

06 · Data and persistence

Memory to reply fast, Mongo so nothing is forgotten.

The bot flow runs on in-memory structures (state, queue, payslip sessions, timers). Everything the dashboard needs after a restart is mirrored to MongoDB Atlas without holding up the reply to the employee: if the database hiccups, the bot keeps answering.

07 · Security

No secrets in the code; no real data in the portfolio.

Token, phone number ID, passwords and addresses live in environment variables, and the HR dashboard only opens with a login. At startup, the logs show only the length of the token and the email password, to confirm they were loaded without exposing their values.

HR dashboard behind a login

All of /admin (dashboard, conversations, contacts, sending messages and attachments, live updates) and the test routes require a username and password, taken from ADMIN_USER and ADMIN_PASSWORD. Without these variables, the dashboard stays locked, never open. The password comparison runs in constant time.

Webhook open only for Meta

/webhook remains reachable, since that is how Meta delivers messages; the initial verification uses the VERIFY_TOKEN from the environment variable.

Environment variables

WHATSAPP_TOKEN, PHONE_NUMBER_ID, VERIFY_TOKEN, MONGODB_URI, SMTP_USER, SMTP_PASS, NOTIFY_TO, NOTIFY_FROM, plus template names and send settings.

Media without exposing the token

Received files are fetched by the server and relayed to the browser; the dashboard never sees Meta's credential. Temporary uploads are deleted after sending.

Sanitized published code

The copy in codigo-original/ is the backend without real credentials. Files with links, passwords, tokens and access details were not included in this public version.

Isolated demo

The published dashboard does not talk to Meta or to any database: calls are intercepted in the browser and answered with five fictional employees.
